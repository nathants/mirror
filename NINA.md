# Project guidelines

- This is Linux-only storage software. Favor explicit, fail-closed state machines over cleverness.
- The only user-facing program is the compiled `cmd/mirror` binary; add functionality as a `mirror` subcommand rather than another entrypoint. Keep shared behavior in normal packages.
- Shell is allowed only for thin `bin/` wrappers that locate the repository and invoke one Go command or the compiled `mirror` binary. Do not put branching, parsing, testing, storage logic, or command pipelines in shell.
- Write simple repository automation as `bin/*.go`, invoke it with `go run`, and use only the Go standard library in those automation programs. The standalone `bin/bake-e2e-image.go` uses `//go:build ignore` to avoid colliding with the checker's main; `bin/check.go` explicitly compiles and analyzes it by filename in addition to package-wide checks.
- Invoke external programs with exact argument vectors through `os/exec`; never route program logic through a shell. Prefer structured machine-readable output over parsing presentation text.
- Storage mutations require a complete preflight, an explicit confirmation before the first destructive action, and immediate state/identity revalidation. Production formatting remains restricted to whole `/dev/sd[a-z]+` disks.
- Format checks every required external tool with device-free version/option probes before selection/confirmation and again before final disk revalidation. Probes use the injected read-only Output boundary with per-tool context deadlines; never pass a device, formatting stdin, or install software. Startup/flag acceptance does not guarantee later kernel or disk success.
- `mirror format`, `mirror mount`, and `mirror unmount` must be launched through sudo and must never invoke sudo internally. Validate sudo's caller metadata against passwd data and use that caller's home directory and ownership.
- Mount/unmount inventory shares identity and topology validation, but only mounting and mounted-root access require writable devices and ext4 on an open mapper. Unmount/close accepts unknown/non-ext4 decrypted filesystems and read-only disks, partitions, or mappers; retain LUKS relationship, expected mapper, holder/mount conflict, confirmation, and state-revalidation checks.
- `internal/inventory` owns the shared util-linux block/mount schemas, block-column selection, strict complete-JSON decoding, tree flattening, and deterministic ordering. Device paths and mount targets must be clean absolute paths; a full findmnt inventory cannot be empty. Keep duplicate/stacked evidence and opaque source strings, including pseudo-filesystems and subvolume suffixes. Format may query targets alone; mount/unmount require sources. Storage eligibility and identity/state revalidation remain in the command packages. Shared checked-in fixtures are sanitized util-linux 2.42.2 captures; tests never invoke host inventory tools.
- Runtime state lives under `~/.mirror/`: `disks` is the configured whole-disk PTUUID list and `repair-last.json` is the atomic resumable repair log. Resume paths must revalidate mounts and listed file state rather than trusting stale log data.
- Disk configuration loading uses nonblocking `openat2` with no symlinks in any path component, verifies an opened regular file, and caps both stat size and streamed input at 65,536 bytes (comments/whitespace included). Context follows reading and parsing through mounted-root discovery and mount/unmount preflight/revalidation. Reject invalid config before inventory; kernel-blocked regular-file I/O is not made interruptible by `O_NONBLOCK`.
- Admin explicitly chose manual recovery for format/mount/unmount: never automatically unmount, close mappers, or roll back on failure. Their CLI handlers hold the operation lock through private, append-only `operations/<command>-<unique>` JSONL logging and independent bounded read-only failure diagnostics. Sync action starts before invoking commands or creating mountpoint directories; record success vs failure/uncertainty without assuming a failed command did nothing. Retain inventory snapshots and earlier logs, mark unavailable diagnostics unknown, and never log passwords/stdin or external command output streams. Copy/repair guard relocking is a separate invariant and remains automatic.
- Tests must never expose host block devices to destructive tools. Real-tool storage tests use disposable image files attached only inside an isolated VM; fast tests inject the operating-system boundary.
- Format/mount/unmount must propagate plan, prompt, status, and table-flush errors. Failed plan/prompt output stops before reading confirmation or starting further mutations; failed status output is an error even after a completed action and does not trigger rollback. Failed decline output is not a silent decline. Preserve the original LUKS-open error alongside retry interaction failures. Terminal confirmation checks prompt output before input; password newline/restoration errors clear and discard the returned password while retaining input errors.
- Tests exercise production code rather than reimplementing it. Run `go run ./bin/check.go` after code changes; it enforces formatting, `go test ./...`, race tests, vet, staticcheck, module consistency, diff whitespace, and thin-wrapper syntax.
- Make hard cutovers. Remove superseded entrypoints and compatibility paths rather than retaining parallel implementations.
- Repair consensus gives each configured mirror at most one contribution per candidate (current data and valid sidecar may support different candidates). Exactly one candidate must exceed half of all configured mirrors, and actual source data must match it. Absent mirrors never shrink the denominator; malformed/missing sidecars do not vote. Repair scans are observational, not ingest.
- `.b2sum` is reserved for checksum metadata, never regular payload files or symlinks; directory names may use the suffix. Reject sidecars of sidecars and of non-regular entries. Ensure refuses checksum-only paths with no regular data source on any mounted mirror. Repair still preserves orphan sidecar evidence, including malformed bytes without votes; never infer payload intent from sidecar contents.
- Ensure preflights the complete data/sidecar destination pair for every missing regular-file copy before unlocking or publication. Any existing sidecar, even matching, requires manual resolution without discarding evidence. Planning and publication share the pair check; no-replace publication remains the final guard. Symlink copies have no sidecars.
- Admin intentionally excludes empty-directory replication. Directories are created only as parents of replicated files or symlinks; empty directories and directory-only trees produce no copy actions, including previews. Do not add directory replication or delete existing empty directories.
- Symlink targets are opaque strings: preserve relative, absolute, dangling, and looping targets exactly, without normalization or following them. Reject target-string disagreements and source-target drift before publication. Confinement applies to filesystem access paths, not target prefixes; external target data is not replicated by copying its link.
- Repair log v4 retains mount-path keys, configured mirror count, exact sidecar-byte hashes plus optional valid checksum values, every unresolved finding/reason, and per-file progress. `BuildLog` returns a valid complete log with `ErrUnresolved` for isolated consensus failures; the command confirms and applies only the independent safe subset. Unresolved evidence is historical and never an apply target; a fresh scan is required after manual resolution. Old log versions require a fresh scan.
- Safe-file progress is synced as pending, started, failed/uncertain, or completed. Persist starts before publication and completion only after desired-state verification. Stop all subsequent repairs on operational or checkpoint failure; report repaired, unresolved, failed/uncertain, and unattempted paths/counts and return nonzero for remaining issues. Resume revalidates mounts and all safe-file evidence; completed files accept only desired bytes and are never repaired again, while unfinished files accept scanned or desired states. Sidecar-only evidence within safe repairs must retain absent data and exact sidecar bytes in both resume and completion.
- Every disk-operation CLI handler, including previews, holds the caller-home `.mirror/operation.lock` flock. Never unlink/replace the lock inode. Propagate context through inventory, prompts, and file I/O; cleanup uses an independent bounded context.
- Ensure/repair command options require explicit fresh mounted-snapshot and output boundaries. Repair confirmation is injected from the CLI, which retains controlling-terminal input and uses the supplied CLI output for prompts; piped stdin is not repair approval. Ensure preview/progress writes propagate errors, stop later actions, and still relock pinned roots after publication failure or cancellation. Completed publications are not rolled back. Full-workflow tests inject inventory/confirmation only and exercise actual scans, publication, journals, and guards on disposable directories.
- External commands use `system.RunCommand` through `Exec`: own a separate process group, kill it on cancellation or abandoned helpers, and verify no live group members (including threads behind zombie leaders) before returning. Keep the leader unreaped through signalling to prevent PGID reuse; never use a concurrent child reaper. Preserve controlling-terminal foreground ownership and modes. Bound inherited-pipe draining separately. This requires visible Linux `/proc` and trusted non-daemonizing tools, not adversarial containment; escaped groups are unsupported, and kernel-blocked exits or lost process visibility may retain the operation lock indefinitely. Subprocess termination never rolls back storage state.
- Directory guards retain one descriptor per mirror root from preflight through relock and close. Normal chmod operations revalidate root paths; cleanup traverses only the original pinned filesystems and chmods opened directory descriptors, even after path loss, while still reporting drift. Never reopen root path strings for relock. Pinned walks retain no-symlink/no-nested-mount confinement and exclude private state and `lost+found`.
- `.mirror-internal/` is a marked private per-disk namespace, excluded from scanning, replication, and chmod walks. Temporary publication files live under `tmp/`; corrupt evidence lives under `quarantine/<unique-record>/<original-relative-path>`. Reject unmarked reserved-path collisions. No automatic evidence deletion or legacy-backup migration.
- Confined filesystem operations use Linux openat2 (kernel 5.6+) with no symlink traversal or nested mounts. Keep external/manual writers off mirror disks during operations; the CLI lock is advisory coordination between mirror processes.
